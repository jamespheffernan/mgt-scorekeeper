# Millbrook Scorekeeper — v2

The v1 application (root `src/`, served by the existing Vite config and Netlify)
remains in place. v2 lives in `/v2/` as a self-contained, modern rebuild and is
kept alongside for direct comparison.

## What v2 is

- A faithful re-encoding of the rulebook at
  [`Millbrook-Game-and-Big-Game-Rulebooks.md`](./Millbrook-Game-and-Big-Game-Rulebooks.md).
  Every value in `v2/src/rules/rulebook.ts` cites the section it implements.
- A pure calculation engine with no React or storage dependencies, exhaustively
  unit-tested (46 tests across strokes, base/doubling, payouts, junk with carry
  + grandé, Big Game, and a 18-hole integration walk).
- A local-first persistence layer using Dexie/IndexedDB, with the Zustand match
  store persisted through it so a refresh resumes on the same hole.
- A distinctive design system: Fraunces serif for display, Geist for body,
  JetBrains Mono for the money column. Country-club ledger palette (fairway
  green, cream paper, brass gold, ink).
- PWA install + offline service worker out of the box.

## What's intentionally **not** in v2 yet

- Firebase auth and cross-device sync (v1 has it; v2 is local-first by default)
- OCR scorecard ingestion
- Ghost player
- Admin debug surfaces
- Multi-tee per-player birdie par (v2 currently uses the first player's tee for
  card par; multi-tee net play is supported)

These were trimmed to ship a tight, well-engineered core. They're additive
later.

## Running v1

```
npm install
npm run dev       # the existing v1 app on port 5173
```

## Running v2

```
cd v2
npm install
npm run dev       # http://localhost:5174
npm test
npm run build
```

## Architecture

```
v2/src/
├── rules/         Frozen rulebook constants + section citations
├── domain/        Entity types
├── engine/        Pure functions (strokes, base, payout, junk, bigGame, ledger)
├── store/         Zustand match store, Dexie-backed persist
├── persistence/   Dexie schema, repos, seed, useLiveQuery
├── courses/       Millbrook scorecard baked from rulebook JSON
├── ui/            Design system (theme tokens + Button/Field/Money/Stepper/…)
├── routes/        Welcome, Setup, Hole, Ledger, Settlement, Roster, Courses
├── lib/           Exports (CSV + PNG), class-name helper
├── App.tsx
└── main.tsx
```

## When to cut over

When the four players who use v1 have run a full round on v2 and verified the
numbers match v1, promote `v2/` to the repo root and archive v1 under
`v1-legacy/`. Until then both apps stand side-by-side.
